# OpenAPI Contract Tests — Mobile ↔ Backend

Verifies that every endpoint called by the mobile app exists in the Django
backend schema and that HTTP methods match.

## Run

```bash
# soft-fail mode (warn on mismatches, test passes)
npx jest src/__tests__/contracts

# strict mode (fail on mismatches)
CONTRACT_STRICT=1 npx jest src/__tests__/contracts

# debug mode (print all endpoints)
CONTRACT_DEBUG=1 npx jest src/__tests__/contracts
```

## Sources of truth

The test resolves the backend schema from one of two sources, in order :

1. **`__fixtures__/openapi-schema.json`** — recommended for CI. Generated by
   `drf-spectacular` :

   ```bash
   cd EventEzBackend
   ./.venv/Scripts/python.exe manage.py spectacular \
     --file openapi-schema.json \
     --format openapi-json
   cp openapi-schema.json ../EventEzMobile/src/__tests__/__fixtures__/
   ```

2. **Static parsing of `apps/*/urls.py` + `@action` decorators** — fallback
   used when the JSON fixture is absent (or in dev where the venv isn't
   handy). Less precise (doesn't resolve serializer schemas) but sufficient
   for path/method validation.

## Files

- `endpointsCollector.ts` — regex-parses `src/api/*.ts` for
  `api.METHOD('/path/...')` and `fetchUpload('METHOD', '/path/...')` calls.
- `schemaExtractor.ts` — loads the JSON fixture or falls back to parsing the
  Django URL conf + DRF ViewSets.
- `openapi.test.ts` — the test itself.

## Common mismatches

- **kebab-case vs snake_case actions** : DRF default is snake_case, but
  some routes override with `url_path='kebab-case'`. The extractor honors
  `url_path` when present.
- **`/api/` prefix** : drf-spectacular schemas typically include `/api/`
  paths but some mobile calls drop it. The test tries both variants.
- **Trailing slash** : Django routes include trailing `/` by default. The
  test tries both with and without.

## Adding a new mismatch waiver

If a mismatch is deliberate (e.g. legacy endpoint kept for backward compat),
add a comment near the endpoint in the relevant `src/api/*.ts` file and
regenerate the schema. There's no formal allowlist yet — keep the warning
volume low and fix mismatches as they appear.
